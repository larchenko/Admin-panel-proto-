# Wheel Swap — план

Веб-додаток: користувач завантажує фото авто, потім фото диска (студійне на білому
фоні або фрагмент диска на іншій машині), вказує розмір поточного диска на фото і
розмір нового. Додаток сам знаходить усі видимі колеса, підганяє новий диск у
перспективу кожного колеса, перемальовує шину під новий розмір і повертає результат.

## Рамки

- Фото авто збоку, у три чверті, ззаду чи спереду під кутом. Фото строго в анфас або
  ззаду, де дисків не видно, не приймаються: додаток так і каже.
- Ручного виправлення немає. Усе автоматично; якщо впевненості немає, колесо
  пропускається і користувач бачить чому.
- Розміри дисків у дюймах (наприклад 16 → 18).

## Розмір дисків: модель

Зовнішній діаметр шини лишається тим самим (так підбирають шини в житті, щоб колесо
лишалося в арці і не змінювався спідометр). Змінюється висота боковини.

```
R  — зовнішній радіус шини на фото (у пікселях, у ректифікованій площині)
r0 — радіус обода на фото
D0 — поточний диск, дюйми (ввів користувач)   D1 — новий диск, дюйми
r1 = r0 · D1 / D0
```

- Боковина [r0, R] перемальовується в [r1, R] радіальним перенесенням текстури
  (протектор біля R не стискається, стискається боковина).
- Якщо `r1 / R > 0.92` — шина «зникає»: обмежуємо і попереджаємо.
- Якщо новий диск менший — боковина розтягується, старий обід закривається гумою.

## Конвеєр

```
фото авто → колеса (YOLOv8m Open Images: Wheel/Tire/Car) → маска (MobileSAM) → еліпси
          → ректифікація (два концентричні еліпси → гомографія)
фото диска → тип (студія / на авто) → вирізати → анфас → добудова симетрією
          → новий обід r1 + перемальована боковина → назад у перспективу
          → світло/колір/шум → краї, перекриття крилом → результат
```

Моделі й залежності беруться лише з PyPI та релізів GitHub (HuggingFace у цьому
середовищі недоступний). GPU немає: усе має працювати на CPU.

Чому не YOLOE: текстові підказки потребують CLIP (не ставиться звідси), а підказка
зразками давала recall ~65%. YOLOv8m, навчений на Open Images, має класи Wheel і Tire
і знаходить майже всі колеса; хибні знахідки відсіює геометрія.

## Цикл якості

1. `make eval` — усі пари «авто × диск × розмір» → `eval/out/metrics.json` + контактні аркуші.
2. Перегляд аркушів, оцінка 1–5: геометрія, масштаб, світло, краї, перекриття, артефакти.
3. Порівняння з попередньою ітерацією в `docs/progress.md`; гірше — відкат.
4. Найгірша категорія → гіпотеза → виправлення → регресійний тест.
5. Коміт і push.

Стоп: усі пороги виконані, середня оцінка ≥4, жодного результату <3, дві ітерації
поспіль без покращення. Або рішення, яке має ухвалити власник, — тоді питання.

## Відомі обмеження

- Глибокі диски з «полицею» — пласкі (диск — плоска текстура).
- Фрагмент диска: видно має бути хоча б третину–половину.
- Розмітка коліс у carparts-seg неповна (багато видимих коліс не позначено), тому
  для оцінки взято Open Images.
