Anatomy

Four parts, top to bottom, and no rules between them — the three zones are held apart by space alone (decision 61): 24px over the wordmark, 16px under it, 16px over the footer. That spacing also keeps the sidebar in step with the page: the wordmark sits on the same optical line as the page title, and the first nav item starts level with the page's tabs.

Areas and icons

Six areas. Order as given: the two things the business is built on first, then the parties around them, then configuration. Labels are the entity name in plural, title case, never a verb. One icon per area, line by default and fill when active (decision 10).

States

The active item carries three cues at once — brand tint, brand text, filled icon — so the item is still findable in greyscale, and still findable after a white-label swap changes the tint. aria-current="page" both triggers the styling and tells a screen reader which area is open.

3px ring in the brand hue. Tab into the list to see it.

aria-disabled="true", 50% opacity, no pointer. For an area the role cannot open — not needed today (one role), kept for the permission matrix later.

Collapsed rail

48px, icons only, labels as tooltips. It buys 208px of table width, which matters on the instruments list. It is a user choice, never a default and never automatic — this is a desktop-only back office (decision 3), so nothing collapses on its own.

Items are square here — size-9, 36×36 around a 20px icon, centred in the rail with an auto margin. The height is the one the expanded item already has, so closing the rail moves nothing vertically; only the width comes in to meet it.

Rules

  • One level. No sub-items and no accordions. Everything below an area is a tab or a filter on that area's screen — the instruments list already carries 13 types as tabs, and those must not be duplicated here.
  • Exactly one active item. A detail screen keeps its area active: an instrument's page still shows Instruments as current.
  • No rules inside the shell. Neither the sidebar nor the page divides itself with a line: the wordmark, the nav and the account block are separated by space, and so are the page title and the list. The one line left is the sidebar's right edge, which separates two different surfaces rather than two zones of the same one (decision 61).
  • The sidebar never scrolls away. Only the page body scrolls (shell-body) — and the page title scrolls with it.
  • The page has no header bar. Its name is the first block inside the body (page-header → page-title, 24px/600), closed by space and not by a rule, with the one action that creates something on the page next to it (decision 60). One h1 per screen, and it is that one.
  • No group labels while there are six items. Grouping helps at ten or more; below that it adds a row of grey text over an obvious list. sidebar-group-label exists for when the list grows.
  • Labels are nouns, plural, title case. "Instruments", not "Manage instruments".
  • The icon is a recognition aid, not the label. Nothing is icon-only except in the collapsed rail, where every item keeps a tooltip.
  • Colour is never the only cue for the active item — see States.

For the developer

hlm-sidebar · the shell: hlm-sidebar-header, hlm-sidebar-content, hlm-sidebar-footer, hlm-sidebar-group, hlm-sidebar-menu, hlm-sidebar-menu-button. Our class names follow those parts one for one.

Variant · Spartan's collapsible="icon" is the collapsed rail above; collapsible="offcanvas" is not used (desktop only).

Active · Helm's isActive input maps to our aria-current="page". Drive it from the router, not from a click handler.

Icons · @ng-icons/remixicon, camel-case names: ri-line-chart-line → remixLineChartLine. Both the line and the fill variant of each of the six icons must be imported.
